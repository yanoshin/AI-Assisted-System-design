# インフラ設計インタビュー

質問に答えていくとインフラ構成の主要決定が固まります。回答は [`design.md`](design.md) に記入。Claude に進めてもらう場合は「infrastructure のインタビューを進めて」と依頼。

質問の体裁は **目的 / 選択肢 / 推奨デフォルト / 参考** の4要素。

---

## H. ホスティング前提

### Q-HOST-01: ホスティング種別は？
**目的**: 全体方針の起点。
**選択肢**:
- A. **パブリッククラウド単独** — AWS / GCP / Azure 等のいずれか1社
- B. **マルチクラウド** — 複数クラウドにまたがる
- C. **オンプレ単独** — 自社データセンター
- D. **ハイブリッド** — クラウド + オンプレ

**推奨デフォルト**: A
**参考**: [service-mapping.md](service-mapping.md)

### Q-HOST-02: クラウド選定は？（A / B / D の場合）
**選択肢**:
- A. **AWS** — シェア最大、サービス最多
- B. **GCP** — Kubernetes / データ系 / Google エコシステム
- C. **Azure** — Microsoft 製品との親和性、エンタープライズ
- D. **その他** — Cloudflare / Vercel / Fly.io / Render など PaaS

**推奨デフォルト**: A
**参考**: 採用後は [service-mapping.md](service-mapping.md) の該当列を参照

### Q-HOST-03: リージョン / マルチリージョン要否は？
**選択肢**:
- A. **単一リージョン** — シンプル・低コスト
- B. **アクティブ-スタンバイ** — DR 用にスタンバイを別リージョン
- C. **アクティブ-アクティブ** — 複数リージョンで同時稼働
- D. **エッジ配信のみ** — CDN/Edge で配信、バックエンドは単一

**推奨デフォルト**: A
**参考**: RTO / RPO は Q-DR-01

## I. コンピュート

### Q-COMP-01: コンピュート種別は？
**選択肢**:
- A. **VM** — 制御度高い、レガシー互換
- B. **コンテナ (マネージド)** — ECS / Cloud Run / AKS
- C. **コンテナ (Kubernetes)** — 大規模・複雑系
- D. **サーバレス関数** — Lambda / Functions

**推奨デフォルト**: B
**参考**: [service-mapping.md §コンピュート](service-mapping.md)

### Q-COMP-02: 配信は？
**選択肢**:
- A. **同一サーバ** — Web/API を1プロセスで
- B. **Web/API 分離** — フロント配信と API を別レイヤに
- C. **CDN + Edge SSR** — エッジで SSR
- D. **完全静的 + API** — フロント静的 + API バックエンド

**推奨デフォルト**: B

---

## J. ネットワーク

### Q-NET-01: ネットワーク分離は？
**選択肢**:
- A. **VPC + パブリック/プライベートサブネット** — 標準的
- B. **VPC + プライベートのみ + Bastion** — DB のみ厳格
- C. **シンプル単一サブネット** — 小規模・検証用
- D. **オンプレ既存ネットワーク** — VPN / 専用線

**推奨デフォルト**: A

### Q-NET-02: パブリック公開範囲は？
**選択肢**:
- A. **CDN + LB を公開、それ以降はプライベート**
- B. **API も直接公開（CDN なし）**
- C. **VPN 経由のみ（社内ツール想定）**

**推奨デフォルト**: A

### Q-NET-03: WAF / DDoS 対策は？
**選択肢**:
- A. **クラウドマネージド WAF** — AWS WAF / Cloud Armor / Front Door
- B. **CDN 付属の防御** — Cloudflare / Fastly
- C. **不要 / 最小限** — 内部ツール

**推奨デフォルト**: A

---

## K. スケーリング

### Q-SCALE-01: スケーリング戦略は？
**選択肢**:
- A. **オートスケール (水平)** — CPU / リクエスト数で自動増減
- B. **手動スケール** — 想定負荷で固定
- C. **垂直スケール** — インスタンスサイズで対応
- D. **サーバレス（自動）** — Lambda / Cloud Run

**推奨デフォルト**: A

---

## L. データ層

### Q-DATA-01: データ層の配置は？
**選択肢**:
- A. **プライベートサブネット必須**
- B. **マネージド DB のエンドポイントを VPC 内に**
- C. **同一サーバ内（小規模・検証）**

**推奨デフォルト**: A

### Q-DATA-02: バックアップ頻度・保存期間は？
**選択肢**:
- A. **1時間毎・7日保管** — 一般的な MVP
- B. **1日1回・30日保管** — 軽量
- C. **継続的 (PITR) + 90日保管** — 高要件
- D. **DR 用に別リージョン複製も追加**

**推奨デフォルト**: A

## M. DR / 可用性

### Q-DR-01: RTO / RPO は？
**選択肢**:
- A. **RTO 4h / RPO 1h** — 一般 Web サービス
- B. **RTO 1h / RPO 5min** — 重要サービス
- C. **RTO 15min / RPO 0** — 金融・決済級
- D. **ベストエフォート** — 検証用

**推奨デフォルト**: A
**参考**: マルチリージョン要否は Q-HOST-03

## N. 監視・ログ

### Q-OBS-01: 監視・ログの集約先は？
**選択肢**:
- A. **クラウド標準** — CloudWatch / Cloud Logging / Monitor

- C. **SaaS** — Datadog / New Relic / Grafana Cloud
- D. **ハイブリッド** — メトリクスは SaaS、ログはクラウド標準など

## O. シークレット・監査

### Q-SEC-01: シークレット管理は？
**選択肢**:
- A. **クラウドマネージド** — Secrets Manager / Secret Manager / Key Vault
- B. **HashiCorp Vault** — マルチクラウド・OSS
- C. **環境変数 + Git 暗号化 (SOPS / git-crypt)** — 小規模

**推奨デフォルト**: A

**選択肢**:
- A. **クラウド標準 (CloudTrail / Audit Logs) を保管 1年**
- B. **専用 SIEM に転送** — 重要システム
- C. **アプリの操作ログのみ** — 監査基盤なし

**推奨デフォルト**: A

## P. CI/CD・IaC

### Q-CICD-01: デプロイ経路は？
**選択肢**:
- A. **CI → コンテナレジストリ → 本番** — 標準的
- B. **CI → IaC apply → 本番** — IaC 主導
- C. **GitOps (ArgoCD / Flux)** — Kubernetes 前提
- D. **手動デプロイ** — 検証フェーズのみ

**推奨デフォルト**: A

### Q-IAC-01: IaC ツールは？
**選択肢**:
- A. **Terraform** — プロビジョニング標準
- B. **Terraform + Ansible** — プロビジョニング + 構成管理
- C. **CDK / Pulumi** — プログラム言語で記述
- D. **クラウド標準 (CloudFormation / Deployment Manager / Bicep)** — クラウド固有

**推奨デフォルト**: B
**参考**: [iac/README.md](iac/README.md)
